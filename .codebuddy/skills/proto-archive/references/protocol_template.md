# 协议条目模板与章节组织

归档到 `memory/pro_<简称>/PROJECT_协议.md`。本文件规定**条目结构**与**表格格式**；协议来源与日期必须记录。

## 一、扩展文件章节组织（PROJECT_协议.md）

```markdown
# <项目名> 协议归档
- 更新日期: YYYY-MM-DD
- 状态: 已归档（或 ⚠ 部分条目待确认）

## 协议清单
| 序号 | 协议名 | 类型 | 位置 | 状态 |
|---|---|---|---|---|
| 1 | 开门指令 | 二进制 | §2 | 已核对 |

## 1. <协议名>（二级标题，每条协议一节）
## 2. <协议名>
...
```

> 命名与格式遵循 init-mem 规范（项目描述扩展文件 `PROJECT_<主题>.md`，主题后缀经用户确认；MEMORY.md 蒸馏时会纳入本文件）。

## 二、单协议条目模板

```markdown
## <序号>. <协议名>

| 项目 | 内容 |
|---|---|
| 类型 | HTTP / MQTT / 二进制 / Modbus / 其他 |
| 用途 | 一句话说明该协议干什么 |
| 来源 | 文档名或链接或文件路径（+ 采集日期） |
| 状态 | 已核对 / 待确认（列出待确认点） |

### 1.1 请求/发起方式
- 方向与触发：<谁发起、什么事件触发>
- HTTP：`POST /api/v1/open_door`（Header：`Content-Type: application/json`；Query：`?dev_id=xxx`）
- MQTT：发布/订阅 `device/{dev_id}/cmd`，QoS 1
- 二进制：帧头 `0xAA 0x55`，命令字 `0x01`，交互时序 <…>

### 1.2 发送内容（请求/上行）
| 字段 | 类型/长度 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| cmd | uint8 | 是 | 命令字 | 0x01 |

（可选：示例报文）

### 1.3 接收/响应内容（应答/下行）
| 字段 | 类型/长度 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| ret | uint8 | 是 | 0=成功 1=失败 | 0x00 |

### 1.4 错误码 / 异常
| 码值 | 含义 | 处理建议 |
|---|---|---|

### 1.5 时序与约束（有则录）
- 心跳间隔 / 超时 / 重试 / 并发限制 / 大小端 / 编码方式（hex/BCD/ASCII）
```

## 三、二进制协议字节布局表（必用）

帧结构需给出**按字节偏移**的布局：

| 偏移 | 字段 | 长度(B) | 取值/类型 | 说明 |
|---|---|---|---|---|
| 0 | 帧头1 | 1 | 0xAA | 固定 |
| 1 | 帧头2 | 1 | 0x55 | 固定 |
| 2 | 命令字 | 1 | 0x01 | 开门指令 |
| 3 | 数据长度 | 1 | N | 数据域字节数 |
| 4~4+N-1 | 数据域 | N | … | 按子协议解析 |
| … | 校验 | 1 | CRC8/异或 | 校验范围注明 |

示例报文（hex）：`AA 55 01 02 00 01 55`（注释每段含义）

## 四、类型速查要点

- **HTTP/API**：Method / URL / Header / Query / Body（JSON 键值表）/ 响应状态码 + Body / 鉴权方式
- **MQTT**：Topic 及通配符（+ / #）/ QoS 语义 / 消息方向（pub/sub）/ Retain / Will 遗嘱 / Payload 字段表 / 心跳（KeepAlive）
- **二进制/自定义帧**：帧头/命令字/长度/数据域/校验/帧尾、大小端、字节对齐、多帧拆包粘包处理
- 数值型字段一律注明：长度、字节序（大端/小端）、编码（hex/BCD/ASCII/UTF-8）

## 五、质量检查（归档前自查）

- [ ] 三要素齐全：请求/发起方式、发送内容、接收/响应内容
- [ ] 字段均为表格，含类型与示例
- [ ] 二进制协议有字节偏移布局表
- [ ] 每个条目记录来源与采集日期
- [ ] 歧义/缺失已标注"待确认"且已向用户提问，无擅自编造
- [ ] 文件头"更新日期"已更新
