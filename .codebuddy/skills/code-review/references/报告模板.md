# 报告模板与定级标准

## 一、定级标准

| 级别 | 含义 | 判定要点 |
|---|---|---|
| 🔴 阻断 | 必须修复后才能交付 | 必现崩溃 / 内存损坏 / 数据错误 / 编译失败 / 违反 P0 硬约束（P0-0、P0-1、P0-2-1、P0-4、P0-5、P0-CPP1~6） |
| 🟠 严重 | 特定条件下故障 | 内存泄漏、竞态、死锁、错误路径未释放资源、错误码语义错、越界风险、**既有对外接口被修改或删除** |
| 🟡 建议 | 健壮性与可维护性 | 参数校验缺失、日志不足、可读性差、性能隐患、单位/量纲混用 |
| 🔵 风格 | 规范性瑕疵 | 命名、注释格式、空行、分隔线等，可批量修 |

定级原则：

- 规范命中按规则自身要求定级；**P0 系列一律不得降级**。
- 缺陷按「发生可能性 × 后果严重度」定级；不确定时给**保守级别**并说明不确定性。
- 同一问题多处命中 → 取更严级别，**合并只报一次**。

## 一·B、精炼异常清单（走查默认输出）

走查完成后**默认只输出本清单**（不展开长报告、不改代码），每条一行、只描述事实：

| 编号 | 级别 | 位置 | 问题（一句话） | 影响 |
|---|---|---|---|---|
| C-01 | 🔴 | `curl/ifaceHttpReq.c:76` | 空指针检查分支内仍解引用 `reply` | 触发即崩溃 |

- 编号规则：`<模块代号>-<序号>`（C=curl、Z=zyEcp、S=string、F=file、T=timeopt、L=linkedList…）。
- **不含修复方案与代码**；用户确认要处理的编号后，进入 `逐条处理流程.md`（方案先行、逐条确认）。
- 用户追问细节或要求落盘时，再输出下面的详细报告。

## 二、详细报告格式（按需展开）

```markdown
# 代码审查报告

- 审查范围: <文件/目录 或 git diff 范围>（共 N 个文件 / M 行）
- 审查依据: .codebuddy/rules/code_general.mdc、code_c.mdc、code_cpp.mdc；
            .codebuddy/skills/code-review/references/*
- 审查时间: YYYY-MM-DD HH:MM
- 结论: 通过 / 有条件通过（需修复 🔴） / 不通过

## 一、概览

| 级别 | 数量 |
|---|---|
| 🔴 阻断 | n |
| 🟠 严重 | n |
| 🟡 建议 | n |
| 🔵 风格 | n |

## 二、问题清单（按级别降序）

### [🔴 阻断] <一句话概括问题>
- 位置: `path/to/file.c:123`（或 `123-140`）
- 类型: 规范符合性 / 代码缺陷
- 依据: `code_c.mdc「禁止项」` 或 `问题模式库 M1` 或推理链
- 问题: <事实描述，附关键代码片段>
- 影响: <后果与触发条件>
- 修复建议: <具体改法；不改代码只给方案>

（同级多条重复此结构）
```

## 三、审查纪律

- **只审查、不改代码**；用户明确授权后才编辑，且先给改动方案与影响面。
- 每条问题必须给出**位置 + 依据**；无依据不列。
- 不臆断：无法确认的写「疑似」并列待确认点。
- 不改规范文件（规范调整属 `rules-code-mgr`）；不代替用户决定是否修复。
- 规则优先于存量代码风格：**不得以"跟随存量风格"为由放过违规**。
- 报告默认输出到对话；用户要求落盘时，输出路径须先确认。
