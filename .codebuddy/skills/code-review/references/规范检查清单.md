# 规范符合性检查清单

本清单**只做条目映射与检出方法**，规范正文以 `.codebuddy/rules/` 下三个规则文件为准，冲突时以规则原文为准：

- `code_general.mdc` — 跨语言通用规范（注释 / 下标 / 错误日志 / 构建约束 / 禁止项）
- `code_c.mdc` — C 专用（文件组织 / 命名 / 函数设计 / 内存 / 嵌入式约束 / 禁止项）
- `code_cpp.mdc` — C++ 专用（GCC 4.7 / C++11 / Qt4 混编）

> 使用方式：逐项核对 → 命中即记「规则文件 + 小节 + 条目号」。规则**未覆盖**的细节（缩进、括号换行等）按 `code_cpp.mdc`「适用范围」与存量风格保持一致，**不判违规**，最多列为 🔵 观察项。

## A. 注释类

依据：`code_general.mdc「注释风格」`、`code_c.mdc「注释风格」`、`code_cpp.mdc「注释风格」`

| 编号 | 检查项 | 检出信号 |
|---|---|---|
| A1 | 所有变量声明必须有用途注释（局部/成员/全局一律） | 声明行无注释 |
| A2 | 所有函数/方法必须有 JSDoc 注释：功能说明 + `@param` + `@return`（void 可省 `@return`） | 函数上方无 `/** */` 块 |
| A3 | **无参函数（含 Qt slot）同样必须有注释** | 形参为空且无注释 |
| A4 | 结构体/类/枚举定义注释用途，**每个成员**注释含义 | 成员行无注释 |
| A5 | 所有 `#define` 必须注释用途 | 宏定义行无注释 |
| A6 | 复杂逻辑必须注释意图：分支多、算法复杂、业务规则非显而易见；位操作/寄存器操作必须注释 | 复杂分支处无注释 |
| A7 | 公开函数文档注释置于 **`.h` 声明处**；实现处不重复标签式注释，实现细节用普通注释补充 | 两处都写 JSDoc / 只在实现处写 |
| A8 | 文件头 `/** 文件用途、作者、日期 */` | 缺文件头 |
| A9 | 注释语言中文；C 统一 `/* */`（禁 `//`），C++ 用 `//` | C 文件出现 `//` 注释 |
| A10 | 行内注释解释"为什么"而非"是什么" | 注释复述代码 |

## B. 命名类

依据：`code_c.mdc「命名规范」「文件组织」`、`code_cpp.mdc「命名规范」「文件组织」`

| 编号 | 检查项 | 检出信号 |
|---|---|---|
| B1 | C：函数小写驼峰；全局 `g_`+小写驼峰；局部小写驼峰；宏 UPPER_SNAKE；typedef PascalCase 或 `_t`；枚举类型 PascalCase；枚举值 UPPER_SNAKE | 命名风格不符 |
| B2 | C++：类 PascalCase；函数小写驼峰；成员 `m`+**大写**驼峰（`mTempValue`）；局部小写驼峰；全局 `g_`+小写下划线；常量/宏 UPPER_SNAKE；类型别名小写短名 | 命名风格不符 |
| B3 | 禁止：变量/函数首字母大写、下划线式变量、类首字母小写、成员缺 `m` 前缀、`m` 后小写 | 命中即违规 |
| B4 | 文件命名：C 两段式 `snake_case.{h,c}`；C++ 两段 `类型_名称.{h,cpp}`；头源同名 | 驼峰/单段/超两段 |
| B5 | 类型别名用 `typedef`/`using`，**禁 `#define`** | `#define` 定义类型 |
| B6 | 结构体命名 `ST_` 前缀（项目约定），字段 camelCase | 不符 |

## C. 结构组织类

依据：`code_c.mdc「文件组织」「变量声明位置」`、`code_cpp.mdc「文件组织」「一个头文件只放一个类」`

| 编号 | 检查项 | 检出信号 |
|---|---|---|
| C1 | include guard：`#ifndef`/`#define`/`#endif`，宏名 `__文件名_H__`；**禁 `#pragma once`** | `#pragma once` |
| C2 | include 顺序：本文件对应 `.h` 置首 → 项目头 → 第三方 → 系统，组间空行 | 顺序错乱 |
| C3 | C89：局部变量必须在函数开头（第一条可执行语句前）声明 | 代码块中间声明 |
| C4 | C++：声明放 `.h`（声明之间**不空行**）、实现放 `.cpp`（实现之间**空一行**）；禁 `.h` 内实现多行方法 / 类外函数（模板、单行 setter/getter 例外） | `.h` 内有函数体 |
| C5 | 一个头文件只放一个类（辅助类型 / 模板及特化例外） | 多头文件多类 |
| C6 | C 头文件必须 `extern "C"` 包裹（`__cplusplus` 守卫） | 缺守卫 |
| C7 | 禁止头文件定义非 const 全局对象（C++） | 头文件内定义对象 |

## D. 逻辑与接口类

依据：`code_general.mdc「禁止项」`、`code_c.mdc「函数设计」「数组传参」「复杂数据传参」「指针空检查」「内存管理」`、`code_cpp.mdc「函数参数传递」「类设计」`

| 编号 | 检查项 | 检出信号 |
|---|---|---|
| D1 | 下标一律从 0 开始，用 `<` 判断边界，**禁 `<=`**（P0-2-1） | `for (i = 1; i <= n; i++)` |
| D2 | 变量必须在**定义处同时初始化**；禁"先定义后赋值"、禁靠 `memset` 补初始化 | 定义与赋值分离 |
| D3 | 数组传参必须同时传长度 + 函数内越界校验；调用方长度用 `sizeof`/变量名，禁字面量 | 数组参数无长度 |
| D4 | 复杂数据必须指针传参：C 结构体 `T *`（只读 `const T *`）；C++ 非基本类型 `const T&` | 结构体/`std::string` 按值传 |
| D5 | 所有指针在使用（解引用、传参）前必须判 `NULL` | 未判空即用 |
| D6 | 公开 API 必须校验指针参数与关键值 | 公开接口无校验 |
| D7 | 返回值仅 `void`/`int`（C 禁 `bool`）；`int` 语义 0=成功、<0=错误码、>0=正常正值；C++ 布尔语义接口可用 `bool` 但不得承载错误码 | 返回 `bool`（C）/ 语义混用 |
| D8 | 单函数 ≤ 80 行；C++ 嵌套 > 3 层须拆分 | 超长/超深 |
| D9 | 栈上分配 ≤ 1024 字节，超限用堆或全局/静态；局部数组长度直接用**字面量**，**禁为其定义宏** | `char buf[2048];` / 为局部数组长度定宏 |
| D10 | 错误码宏定义为**正数**，返回时加 `-`；禁错误码宏定义为负数 | 负数宏 / 不加 `-` |
| D11 | C++ 成员变量初始化：类内初始化优先，依赖构造参数的用初始化列表；**禁构造函数体内赋值**（P0-CPP2） | 构造体内赋值 |
| D12 | C++ 类设计：基类析构必须 `virtual`（P0-CPP4）；构造/析构禁调用虚函数（P0-CPP3）；不修改成员的成员函数必须 `const`（P0-CPP5） | 命中即违规 |
| D13 | 单例用 Meyer's Singleton（static 局部变量 + 拷贝赋值 `= delete`）；接口用 `I` 前缀纯虚类 | 不符 |
| D14 | 全局状态：C 模块内用 `static` 文件作用域；**禁跨模块非 const 全局变量**；C++ 全局集中于 `global.cpp` 定义 + `extern` 导出（`include/global.h`） | 跨模块非 const 全局 |
| D15 | C++ 禁 C 风格强制转换 `(type)expr`（P0-CPP1）、禁隐式指针转换（C） | 命中即违规 |

## E. 错误处理与日志类

依据：`code_general.mdc「禁止项」`、`code_c.mdc「错误处理与日志」`、`code_cpp.mdc「错误处理与日志」`

| 编号 | 检查项 | 检出信号 |
|---|---|---|
| E1 | **错误返回分支必须打日志**：凡判断返回值出错（`ret < 0`、参数校验失败等）的分支必须 `LOG_E`（含错误码/原因），**禁静默返回** | 失败分支直接 `return` |
| E2 | 错误优先 + 提前退出；正常流程零嵌套 | 正常逻辑深嵌套 |
| E3 | `goto` **仅限**错误处理且需释放资源的场景（局部、单向）；禁其它跳转 | 非错误处理用 `goto` |
| E4 | 日志 `LOG_I`/`LOG_E`/`LOG_D` 内容全中文、不加前后缀；`lib_log_init()` 必须先于所有 `LOG_*`；C++ `main()` 第一行业务代码必须是 `lib_log_init()` | 顺序错 / 加前缀 |
| E5 | 有资源释放需求时用「goto 清理出口」模式：失败跳转统一清理 | 错误路径未清理 |

## F. 禁止项对照表

依据：`code_c.mdc「禁止项」`、`code_cpp.mdc「禁止项」`、`code_general.mdc「禁止项」`

**C（逐条核对）**：`#pragma once` / `//` 注释 / VLA 与 `alloca` / `strcpy`·`strcat`·`sprintf` / 代码块中间声明变量 / 数组传参不带长度 / 调用方写死长度数字 / 结构体按值传参 / 指针未判空使用 / 栈上 >1024 字节 / 跨模块非 const 全局变量 / 返回 `bool` / 错误分支不打印日志 / 隐式指针转换 / `goto` / 魔法数字裸用 / 局部数组长度用宏 / `scanf` / 1 起始下标 / 手动修改 Makefile

**C++（逐条核对）**：裸露 `new`/`delete` / 头文件 `using namespace std` / C 风格强制转换 / 与 C 混编缺 `extern "C"` / 头文件非 const 全局对象 / 嵌套 >3 层 / `goto` / 魔法数字裸用 / 局部数组长度用宏 / `#pragma once` / `.h` 内实现方法或类外函数 / 非基本类型按值传参 / 错误分支不打日志 / 异常与 RTTI / C++14 特性（`make_unique`、`auto` 返回推导、泛型 lambda、`_t` 别名、`cbegin`/`cend`、二进制字面量、数字分隔符）/ C++17+ 特性（`if constexpr`、折叠表达式、结构化绑定、`optional`、`variant`、`[[maybe_unused]]`）/ 构造体内赋值 / 构造函数调虚函数 / 基类非虚析构 / 手动 `delete` QObject 子对象 / 1 起始下标 / 手动修改 Makefile / `#define` 定义类型别名 / 错误码宏定义为负数

**通用**：注释为违规代码"开脱"（P0-0）/ 错误分支静默返回 / 1 起始下标（P0-2-1）/ 魔法数字裸用 / 定义与初始化分离 / 手动修改 Makefile（P0-1，须改 `.pro` 后重新生成）

**例外（不判违规）**：局部数组长度直接写字面量，且**不受**"禁止魔法数字"约束（`code_c.mdc` / `code_cpp.mdc`「局部数组长度」）。

## G. 判定与记录

- 命中项记录格式：`规则文件「小节」条目` 或 `P0-x` 编号。
- P0 系列（P0-0/1/2-1/3/4/5、P0-CPP1~6）**一律不得降级**。
- 规则未覆盖处 → 不判违规，列 🔵 观察项。
- 同一问题在 A~F 多处命中时，取最严级别**合并只报一次**。
