# rules 文件命名规范（固定前缀 code、无序号）

编码类 rules 统一放在 `.codebuddy/rules/` 下。

## 拆分决策规则

| 场景 | 拆分方式 | 示例文件 |
|------|----------|----------|
| 同一语言的多主题规范 | 合并为一个文件（一个语言一个文件） | `code_cpp.mdc`（含版本特性/注释/禁止项/示例） |
| 跨语言通用的主题 | 独立成文件（注释风格、命名约定等通则） | `code_comment.mdc`、`code_naming.mdc` |
| 语言文件与通用文件重叠 | 通用文件放"通则"，语言文件放"特例"并互相引用 | `code_comment.mdc` 定通则，`code_cpp.mdc` 引用并补充 C++ 特例 |

## 命名格式

```
code_<语言或通用主题>.mdc
```

- **前缀**：固定 `code`（编码类统一标识，**不使用序号**）
- **主体**：语言名（`cpp`/`c`/`python`）或通用主题（`comment`/`naming`），小写 + 下划线
- **后缀**：`.mdc`

## 文件名确定流程

文件名由三步推导（不是凭空取名）：

**Step A 判定归属类型**（决定主体词是语言名还是主题词）：
- 规则只适用于**单一语言** → 语言文件，主体 = 语言名
- 规则适用于**多种/所有语言** → 通用主题文件，主体 = 通用主题词

**Step B 查重**（结合 Step 0 盘点）：
- 已有同语言文件（如 `code_cpp.mdc`）→ **并入现有文件**，文件名不变，不新建
- 已有同主题文件（如 `code_comment.mdc`）→ 并入
- 无对应文件 → 新建，进入 Step C

**Step C 生成文件名并校验**：
- 格式 `code_<主体>.mdc`；主体词小写 + 下划线
- 语言名用约定俗成缩写（`c`/`cpp`/`python`）；通用主题词用表意清晰的名词（`comment`/`naming`/`error_handling`）
- 校验：无空格/中文/大写驼峰/序号；主体词不与语言名混淆

| 需求 | 判定 | 文件名 |
|------|------|--------|
| C++ 编码规范 | 单语言 → `cpp` | `code_cpp.mdc` |
| 所有语言注释规范 | 跨语言 → `comment` | `code_comment.mdc` |
| C++ 禁止裸指针 | 单语言 + 已有文件 | **并入** `code_cpp.mdc`，不新建 |

## 示例

| 文件名 | 含义 |
|--------|------|
| `memory_load.mdc` | 记忆加载桥接（非编码类，本 skill 不管理，保留原名） |
| `code_cpp.mdc` | C++ 编码规范（含该语言全部主题） |
| `code_c.mdc` | C 编码规范 |
| `code_python.mdc` | Python 编码规范 |
| `code_comment.mdc` | 跨语言通用注释风格规范 |
| `code_naming.mdc` | 跨语言通用命名约定 |

## 硬性要求

1. **固定前缀**：所有编码类 rules 以 `code_` 开头，无序号 → `ls .codebuddy/rules/` 或 `rg -l 'code_'` 一次检索全部编码规则
2. **按语言分文件**：同一语言的多主题规范不得拆散为多文件
3. **跨语言才独立**：仅跨语言通用主题独立成文件（通则），语言特例留在语言文件内并引用通则
4. **命名禁则**：禁止空格、中文、大写驼峰、特殊字符（除 `_`）、序号数字前缀
5. **同名禁止**：同一主体（语言/主题）不得重复建文件；改主体即改文件名（连同 SKILL 内引用）

## 检索方法

```bash
# 列出全部编码类规则
ls .codebuddy/rules/code_*.mdc

# 按主题检索
rg -l "主题关键词" .codebuddy/rules/code_*.mdc
```
