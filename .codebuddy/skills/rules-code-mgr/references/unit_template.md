# 编码类 rules 单元模板

每个编码类 rules 文件 = frontmatter + 正文必备单元 + 个性化挂载点。此模板可直接套用。

## 完整模板

```markdown
---
description: <一句话说明规则适用范围与触发场景>
globs: "<文件匹配模式>"   <!-- 不限定可省略此行 -->
---

# <规则主题> 编码规范

## 适用范围

<适用语言 / 项目 / 文件类型 / 场景>

## 编程语言

- 语言：<目标语言>
- 语言版本特性（按需）：<仅记录影响编码的版本差异；AI 已知的通用特性不详细描述>

## 注释风格

<注释格式要求：文件头 / 函数头 / 行内；语言要求；示例>

## 禁止项

- <明确不允许的行为 1>
- <明确不允许的行为 2>

## 正向示例

```<语言>
// 正确：<符合规范的写法>
<代码>
```

## 反向示例

```<语言>
// 错误：<违反规范的写法>
<代码>
```

## 个性化扩展

> 本单元为扩展挂载点：可根据项目/用户需要自由追加模块化小节，不破坏既有结构。
> 追加时保持小节独立、命名清晰、编号递增（## 个性化扩展 1、## 个性化扩展 2 …）。

### 个性化扩展 1
<!-- 追加内容：项目专属命名约定 / 团队规范 / 工具链约定等 -->
```

## 单元验收点

| 单元 | 验收 |
|------|------|
| frontmatter | 有 `description`；有 `globs` 则格式合法 |
| 适用范围 | 明确写出适用对象 |
| 编程语言 | 语言名明确 |
| 语言版本特性 | 不强制指定版本；有记录则准确反映语言能力差异 |
| 注释风格 | 可执行（含示例或明确格式） |
| 禁止项 | 负面约束明确、可操作 |
| 正向示例 | 与规范/禁止项对应，可编译语义正确 |
| 反向示例 | 与禁止项一一对应，标注"错误"原因 |
| 个性化挂载点 | 存在，格式固定，编号规则清晰 |
