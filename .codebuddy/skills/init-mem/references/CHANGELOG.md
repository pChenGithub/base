# init_mem 变更记录

本文件登记记忆体系的演进历史。体系固定（v1.0）前，每次结构调整在此追加。

## v0.1 — 2026-08-31

**初始版本。** 体系处于持续演进阶段，尚未固定。

- 确立双层结构：`source/`（蒸馏依据）与 `MEMORY.md`（蒸馏产物）物理分离
- 明确数据流：source/ 为唯一真相源，MEMORY.md 为可重建的派生产物
- 定义文件命名规范：`NN_主题.md`、`YYYY-MM-DD.md`
- 定义三类资源内容边界（memory / rules / skills）
- 制定创建/修改记忆文件的检查清单（结构、命名、格式、边界、同步、交付）

**当前状态：** 演进中，等待实际使用反馈后迭代。

## v0.3 — 2026-08-31

**命名规范确立：** 经用户澄清确认，固化命名规则（四项决定）。

- 命名语言：英文固定名 + 中文主题
- 核心文件：英文固定名 `MEMORY.md` / `PROJECT.md` / `PROFILE.md`（原 `00_project.md` / `01_profile.md` 更名）

## v0.11 — 2026-09-01

**检查流程明确化（经用户确认）：** 固化校验合规性的检查顺序与要点，支持多项目。

- **检查流程重排为 6 步**：
  1. 检查用户画像 `PROFILE.md`：必备组件、**项目公用**、跨项目共享、持续迭代
  2. 确认当前项目信息：检查前必向用户确认项目名称，总结/缩略为简称（必要时询问确定），再查 `pro_<简称>/` 文件夹
  3. 检查项目文件夹内容：**必须有 `PROJECT.md`**（四要素）**与 `logs/`**（该项目 AI 工作日志）
  4. 检查蒸馏记忆 `MEMORY.md`：由 **用户画像 + 项目文件 + 项目日志** 蒸馏而来，**禁止直接编辑**
  5. 边界与格式检查：内容归属、元信息、append-only、去重
  6. 同步标记：素材变更 → 标记 → 蒸馏 → 清除
- **支持多项目**：`pro_<简称>/` 文件夹可有多个（多项目协同开发），每项目一个文件夹，PROFILE.md 与 MEMORY.md 保持共享

- **日志归属规则补充（方案 A，经用户确认）**：项目工作 → 该项目 logs/；无主工作（体系调整/跨项目公共工作/画像维护）→ 当前操作项目 logs/，不设公共日志目录（structure.md ④ 部分固化）
