# 内容边界

## 一、memory 内部四部分边界

| 内容 | 归属 | 禁止 |
|---|---|---|
| 项目概述、功能、技术栈、架构、数据流 | ② `pro_<简称>/PROJECT.md` | 混入用户主观偏好、工作过程 |
| 用户思考链路、处事习惯、性格、母语 | ③ `PROFILE.md`（**项目公用，跨项目共享，持续迭代**） | 混入项目事实、过程记录 |
| 工作过程、决策、踩坑、验证结果 | ④ `pro_<简称>/logs/*.md` | 混入精炼结论（应进 MEMORY） |
| 跨会话必知结论、关键约定 | ① `MEMORY.md` | 直接追加新信息（应走素材→蒸馏） |

**PROFILE 四要素（思考链路/处事习惯/性格/母语）为内容框架（软性，v0.17 确认）**：有则记录、无则空缺，不强制每要素必填；只硬性要求 PROFILE 存在且非空。

**用户画像扩展文件（`PROFILE_<主题>.md`）边界**：仅放用户特质（如技术偏好细节、工作流程偏好）；坑点、编码规范、检查点等归 rules 或 skill，不得写入扩展文件（v0.14 确认，示例修正：`PROFILE_调试坑点.md` 不再使用）。

## 二、memory / rules / skills 外部边界

### memory/（本 skill 管理范围）

**记录内容：**
- 项目定位、需求描述、功能清单、技术栈、架构
- 用户画像（思考链路、处事习惯、性格、母语）
- AI 工作日志、历史决策

**禁止放入：**
- 编码规范、检查点、坑点（→ `rules/`，不属本 skill 管理）
- 规则文件（.mdc）
- 与项目无关的个人内容

### rules/（官方自动加载，非本 skill 管理）

**记录内容：**
- 代码强制校验标准、硬性约束（P0 级）
- 桥接规则（如"新增接口前必须使用 `fetch-api-docs` skill"）
- 适用范围登记表

**禁止放入：**
- 项目背景、需求、架构详情（→ memory）
- 冗长的规范细节（→ skill references）

### skills/（按需触发，非本 skill 管理）

**记录内容：**
- 完整工作流（端到端流程：按规范执行 + 检查 + 纠正）
- 规范细节库、检查点清单、坑点库
- 元规则（如 rules-writer：规范 rules 的创建流程）

**禁止放入：**
- 项目背景（→ memory）
- 每会话必生效的硬约束（→ rules）

## 判断口诀

- "项目是什么" → PROJECT
- "用户是怎样的人" → PROFILE
- "做过什么" → logs
- "必须记住的结论" → MEMORY（蒸馏）
- "代码必须怎么要求" → rules（少量核心）
- "代码应该怎么写" → skills（完整细节）
