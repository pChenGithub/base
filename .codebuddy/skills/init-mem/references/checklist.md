# 记忆文件检查清单

创建或修改 `memory/` 目录文件时，逐项核对。全部通过才可交付。

## A. 结构检查

- [ ] 文件位于正确的部分：项目事实→`pro_<简称>/PROJECT.md`，用户特质→`PROFILE.md`，过程→`pro_<简称>/logs/`，结论→`MEMORY.md`
- [ ] **`PROFILE.md` 存在且非空（必备组件，项目公用、持续迭代，缺失即不合规）**
- [ ] 未在 memory/ 根目录散落无关文件（仅允许 `MEMORY.md`、`PROFILE.md` 及 `pro_<简称>/` 项目文件夹）
- [ ] **支持多个 `pro_<简称>/` 项目文件夹**（多项目协同开发，每项目一个文件夹）
- [ ] **每个 `pro_<简称>/` 内必须同时含 `PROJECT.md`（项目描述）与 `logs/`（该项目的 AI 工作日志）**
- [ ] 工作日志仅位于 `pro_<简称>/logs/`，未在根目录或项目文件夹外创建其他日志目录

## B. 命名检查

- [ ] 项目文件夹命名正确：`pro_<项目简称>/`（简称=项目名称缩略）
- [ ] 项目文件夹名**必不为空、必不省略**：禁止根目录下散落的 `PROJECT.md`
- [ ] 创建/校验项目描述文件时，已向用户确认项目名称与简称
- [ ] 项目描述主文件为固定名 `PROJECT.md`（位于项目文件夹内）
- [ ] 核心固定文件命名正确：`MEMORY.md` / `PROFILE.md`（英文固定名，无编号前缀）；**`PROFILE.md` 必不为空、必不省略**
- [ ] 扩展主题文件命名符合 `主名_后缀.md`（主名与后缀间下划线隔开；后缀为英文时单词**首字母大写组合、不用下划线**）且位于所属文件夹内，如 `PROJECT_AiCorrections.md`、`PROFILE_技术偏好.md`
- [ ] 扩展文件后缀在创建前已询问用户确定
- [ ] 日志文件符合 `pro_<简称>/logs/YYYY-MM-DD.md`
- [ ] 文件名不含空格、`\ / : * ? " < > |` 等特殊字符

## C. 格式检查

- [ ] `pro_<简称>/PROJECT.md` / `PROFILE.md` 头部含 `# 标题`、`- 更新日期`、`- 状态`（注释式文本）
- [ ] 项目描述内容完整：包含项目概述 / 项目技术栈 / 项目架构 / 项目模块四要素（模块详细需求/功能视具体需求而定）
- [ ] MEMORY.md 头部含蒸馏时间戳、依据文件清单、状态标记（需重新蒸馏/已同步）
- [ ] MEMORY.md 未在会话中被直接追加新信息（应走素材 → 蒸馏）
- [ ] 日志条目为 append-only，未修改历史条目
- [ ] 日志条目格式统一为 `- [HH:MM] 主题：内容`（不使用 `## 小节标题` 组织，v0.14 起；**宽限**：新格式生效前已存在的**历史写法**日志（小节式 / 段落式等任意旧写法）按 append-only 豁免、不判不合规，v0.19 / v0.21；**宽限范围的变更须用户确认，v0.20**）
- [ ] 日志条目 `[HH:MM]` 为**真实本地时间**（写条目前先取系统时间，禁止按对话节奏估算，v0.22）；历史偏差标签按 append-only 保留、只可追加补记，不得回改
- [ ] 日志文件首行为 `# YYYY-MM-DD 工作日志`（历史不一致写法按 append-only 宽限、不判不合规，v0.24）
- [ ] 文件末尾无空行堆积、无未闭合的代码块

## D. 内容边界检查

- [ ] 项目客观事实（概述/技术栈/架构/模块及需求）→ pro_<简称>/PROJECT.md，未混入用户主观偏好
- [ ] 用户特质（思考链路/处事习惯/性格/母语）→ PROFILE.md（项目公用、持续迭代），未混入项目内容；四要素为内容框架（有则记录、无则空缺），只硬性要求 PROFILE 存在且非空（v0.17）
- [ ] 工作过程/决策/踩坑 → pro_<简称>/logs/，未混入精炼结论
- [ ] 精炼结论/跨会话约束 → MEMORY.md（蒸馏产生）
- [ ] 未混入编码规范/检查点/坑点（应属 `rules/`，不属本 skill 管理范围）
- [ ] 无重复登记已有信息（先查现有文件再写）
- [ ] 日志仅记录**与具体项目相关**的工作；**体系维护类**工作（skill / rules 调整、记忆体系检查与维护、画像维护）未写入项目日志（其痕迹记录方式不属本 skill 管理范围）（v0.23 / v0.29）

## E. 同步检查

- [ ] 素材（②③④）关键内容（定位/架构/关键约定/协作要点等）实质变化时，MEMORY.md 已实时蒸馏刷新（v0.18）
- [ ] 一般性变更（常规工作日志追加等）已标记 `⚠ 需重新蒸馏`（未逐条触发蒸馏）；**体系维护流程完成后已自动刷新**（v0.16 例外）
- [ ] 蒸馏完成后，标记已清除，时间戳与依据清单已刷新
- [ ] 当日**项目**工作已登记到该项目 `logs/`（体系维护类不记日志，v0.23）

## F. 交付规范

- [ ] 交付时首行给出文件完整路径
- [ ] 全文重建 / 首次创建类交付 → 输出完整内容；**增量修改 → 只给变更点（路径 + 改动项）**，不重复输出未改内容（v0.24）
- [ ] 变更已登记到 references/CHANGELOG.md（如涉及体系调整）
- [ ] 校验不合规时，已先与用户澄清确认，再修改保存（未经确认不改动已有内容）
- [ ] 新增/修改扩展文件时，后缀已获用户确认
- [ ] 创建/校验项目描述文件时，项目简称已获用户确认（必不为空、必不省略）
- [ ] 记忆体系必备组件齐全：MEMORY.md / pro_<简称>/PROJECT.md / PROFILE.md / pro_<简称>/logs/ 均存在

## G. 新项目初始化检查（v0.12）

- [ ] 用户说"创建项目 XX / 创建新项目 XX"时已响应（触发方式为显式指令）
- [ ] 已向用户确认项目名称，并总结/缩略简称（必要时询问确定），未确认前未创建文件夹
- [ ] 已创建 `pro_<简称>/` 文件夹（含 `logs/` 子目录）
- [ ] PROJECT.md 初始化符合视情况原则：有代码仓库 → code-explorer 提炼完整四要素；无代码 → 骨架占位（架构/模块标"待补充"）
- [ ] PROJECT.md 头部含元信息（`# 标题`、`- 更新日期`、`- 状态`）
- [ ] 已在 `pro_<简称>/logs/YYYY-MM-DD.md` 登记初始化日志
- [ ] 新项目素材加入后：按 v0.18 优先**实时蒸馏**刷新 MEMORY.md；无法即时蒸馏时才标记 `⚠ 需重新蒸馏`
- [ ] 蒸馏时已汇总所有项目素材（全部 pro_<简称>/ 的 PROJECT.md + logs/ + PROFILE.md）

## H. 多项目协同检查（v0.13~v0.23）

- [ ] 当前操作项目已确定：按目录/项目特征推断；memory/ 下仅一个项目时默认其为当前操作项目；多项目且无法推断时已询问用户（不擅自猜测）
- [ ] MEMORY.md 按项目分节组织（公共节：体系规则/用户协作要点 + 每项目一节：定位/架构/关键约定），画像与体系规则为公共节
- [ ] 扩展文件拆分：明细明显偏大时 AI 已主动提议，后缀经用户确认后拆分（未擅自拆分）
- [ ] 无停维护归档操作（`memory/archive/` 不建立；不考虑停止维护项目）
- [ ] PROFILE.md 仅在用户明确要求时更新（未自动追加观察记录；观察到新特质已直接丢弃、不写日志）
- [ ] 完整合规检查仅在用户明确要求时触发；检查对象为**全部 `pro_<简称>/` 文件夹**（逐项检查 PROJECT.md + logs/ 及格式边界，全部合规才交付）
- [ ] 版本冻结：仅当用户明确宣布"冻结 v1.0"时执行（AI 不主动提议）

## I. 迁移与宽限检查（v0.20 / v0.25）

- [ ] 涉及既有文件迁移（移动 / 重命名 / 改写位置或格式）时，已在**执行前**提出提案并获用户确认；未获确认的保持原状
- [ ] 提案已列明四项：待迁移文件清单（原路径 → 目标路径）、方式（移动 / 复制 / 改写）、是否改动内容、宽限对象与理由
- [ ] 未自行判定宽限（未擅自放宽或收紧）；v0.19 已确认的历史日志宽限按原范围适用
- [ ] 未将某项目确认的宽限自动推广到其他项目（跨项目适用已另行确认）
- [ ] 迁移 / 宽限执行后**未作任何记录**（不写项目日志、不登记 `CHANGELOG`，v0.26）
- [ ] **项目记忆迁移**（文件夹改名 / 简称变更 / 跨仓库搬迁 / 合并 / 拆分）已在执行前提出提案并获用户确认；未获确认保持原状（v0.25）
- [ ] 原项目记忆**任何文件未改动**（不改写 / 不移动 / 不重排），仅作为蒸馏的事实依据；旧位置文件已保留，删除 / 覆盖已单独确认（v0.26）
- [ ] 迁移产物 `PROJECT.md` 系**由原项目记忆蒸馏**并按格式形成（四要素 + 头部元信息齐全），非照搬旧文件；`MEMORY.md` 由蒸馏重建，未手工搬（v0.25 / v0.26）
- [ ] 迁移本身**未作任何记录**（不写项目日志、不登记 `CHANGELOG`，v0.26）
